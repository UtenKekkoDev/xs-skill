# 修订与连续性检查

## 修改范围

把用户修改意见转成「问题 / 涉及情节 / 所需调整 / 检查结果」。用户要求严格落实时逐条核对，不仅进行语言润色；意见之间矛盾或与不可更改项冲突时指出具体冲突，只询问影响决定的部分。

精修优先保留核心情节与现有章序；大修可以在授权范围内调整结构。修复问题后同步检查前后相关场景，避免只改一句造成新矛盾。

## 连续性台账

根据作品复杂度选用以下字段，不必向用户输出全套表格。

| 项目 | 核对内容 | 常见缺口 |
| --- | --- | --- |
| 时间线 | 日期、时段、倒计时、路程耗时、恢复耗时 | 一小时完成多次长途转移；截止时间忽然延长 |
| 位置与动作 | 谁在何处，谁能看见或听见谁，进出路线 | 人物突然出现在密闭现场；动作主体混乱 |
| 知识边界 | 谁在何时通过什么渠道知道事实 | 未见证者知道秘密；第一人称提前知道幕后真相 |
| 动机与关系 | 欲望、利益、底线、破例原因与代价 | 无理由信任或背叛；一句话改变长期执念 |
| 能力与规则 | 生效条件、限制、代价、例外及其铺垫 | 高潮新增免疫；契约只在方便时生效 |
| 道具与证据 | 获取、持有、转交、消耗、损毁、可验证性 | 戒指或钥匙瞬移；证据来源不明 |
| 伤势与资源 | 伤势程度、后续影响、恢复方式、资源余额 | 重伤后无代价战斗；消耗品无限使用 |
| 伏笔与悬念 | 埋设、解释、兑现、遗留是否有意 | 反复强调的线索无作用；章末危机下一章消失 |

对于关键胜负，确认行动链完整：主角凭什么想到办法，如何执行，对手为什么不能简单阻止，结果为什么能成立。

## 分层修订

先修目标、因果、信息与人物选择，再修章节顺序和场景衔接，最后精简语言。因果未成立时，不用更有气势的句子掩盖问题。

逐章核对：

- 章首两三句是否给出真实冲突或异常，是否接得上前章。
- 本章人物要完成什么，采取什么行动，付出什么代价。
- 场景结束后，关系、资源、信息或风险有何变化。
- 章末悬念是否来自本章，并在后文获得回应；末章是否完成落点。

语言检查：代词与动作主体清楚，转场有必要时间和位置提示，对话符合身份，修辞不重复，情绪不反复解释。若缩短篇幅，优先删重复确认和无变化过程，保留决定性线索、代价与反击。

## 修改记录与交付

用户要求批注时，在正文外逐章列出「原问题 / 修改动作 / 解决效果」，或使用指定格式的文档批注。没有实际执行的项目不得标记完成。

提交前核对修改意见覆盖、不可更改项保留、连续性与字数口径。输出完整授权范围内的修订内容；检查摘要只报告实际核对的事项，避免空泛宣称所有逻辑毫无问题。
